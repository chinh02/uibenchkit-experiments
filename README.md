# UIBenchKit Experiments

This repository stores lightweight submission manifests and derived leaderboard
files for UIBenchKit. Heavy raw artifacts are stored on Hugging Face:

```text
https://huggingface.co/datasets/chinh02/UIBenchKit
```

Use this repository when you want to submit new UI-to-code benchmark results.
The expected contribution flow is:

1. Run an experiment with UIBenchKit.
2. Upload the completed raw run artifact folder to Hugging Face.
3. Regenerate leaderboard files with `summarize_leaderboard.py`.
4. Open a merge request with a small `submissions/*.json` manifest and the
   regenerated leaderboard outputs.

## Ecosystem Role

UIBenchKit is split across companion repositories:

- `UIBenchKit`: backend API, local runner, model wrappers, method integrations,
  rendering, and evaluation.
- `uibenchkit-cli`: command-line client for submitting and managing backend
  runs.
- `uibenchkit-GUI`: public web interface for leaderboard browsing, model/method
  comparison, result submission guidance, and live demos.
- `uibenchkit-experiments`: this repository, containing raw experiment results
  and generated leaderboard data.

The data flow is:

```text
UIBenchKit run artifacts
  -> Hugging Face dataset: chinh02/UIBenchKit/<run_id>/
  -> submissions/<run_id>.json
  -> python summarize_leaderboard.py
  -> leaderboard/*.csv and leaderboard/*.json
  -> UIBenchKit GUI leaderboard views
```

## Repository Layout

```text
uibenchkit-experiments/
  submissions/
    <run_id>.json            # lightweight pointer to Hugging Face artifacts
  raw-data/
    README.md                 # explains why raw artifacts are not committed
  leaderboard/
    comparison_dcgen.csv
    comparison_design2code.csv
    dcgen-results.json
    design2code-results.json
    trajectory_links.json
  summarize_leaderboard.py
  token_split_methodology.md
```

`raw-data/` is ignored by Git except for its README. It may be used as a local
cache while debugging, but new submissions should target `submissions/`.

## Accepted Raw Run Format

Each submitted run must have a corresponding artifact folder on Hugging Face.
The Hugging Face artifact path should follow:

```text
<dataset>_<method>_<model>_<YYYYMMDD>_<HHMMSS>
```

Examples:

```text
dcgen_direct_gpt-4o_20260102_092937
design2code_dcgen_claude-3-7-sonnet-20250219_20260115_030000
dcgen_latcoder_gpt-5_20260212_022005
```

The summarizer parses the folder name to infer dataset, method, model, and run
timestamp. Keep model names filesystem-safe and consistent with UIBenchKit
output naming.

The Hugging Face artifact folder should contain:

- `evaluation.json`: metric results generated by UIBenchKit.
- `run_metadata.json`: run configuration and status.
- `results.json`: per-instance result status and generated file paths.
- `cost_report.json`: token and cost summary.
- Generated `<sample_id>.html` files.
- Rendered `<sample_id>.png` screenshots.
- Method-specific artifact folders, if produced by the run.
- `token_details.json`, only when the built-in token split cannot be derived
  from `cost_report.json` and artifacts.

Do not include API keys, `.env` files, private datasets, or unrelated local
cache files.

## Generate Results With UIBenchKit

From the backend repository:

```bash
cd <path-to-UIBenchKit>
python run.py preflight

python run.py run \
  --input ./data/demo \
  --method direct \
  --model gpt4 \
  --run-id dcgen_direct_gpt-4o_20260102_092937
```

Or through the API/CLI:

```bash
uibenchkit submit gpt4 direct --dataset dcgen --sample-ids 0,1,2
uibenchkit poll <run_id> --watch
uibenchkit get-report <run_id>
```

For leaderboard submissions, prefer complete benchmark runs over tiny smoke
tests. If you submit a partial run, make that clear in the merge request
description.

## Add A New Submission

From this repository:

```bash
cd <path-to-uibenchkit-experiments>
```

Create a manifest under `submissions/`:

```text
submissions/<run_id>.json
```

Example:

```json
{
  "run_id": "dcgen_direct_gemini-3-pro-preview_20260110_030916",
  "dataset": "dcgen",
  "method": "direct",
  "model": "gemini-3-pro-preview",
  "artifact_source": "huggingface",
  "artifact_repo": "chinh02/UIBenchKit",
  "artifact_repo_type": "dataset",
  "artifact_revision": "a107b7da78ce3c15c6bd5b204e3bcc9024b9a76e",
  "artifact_path": "dcgen_direct_gemini-3-pro-preview_20260110_030916",
  "uibenchkit_version": "main",
  "notes": ""
}
```

For quick local debugging, you may also place a local copy of the run folder
under `raw-data/<run_id>/`. Local raw-data folders are ignored by Git and should
not be committed.

Then regenerate the derived leaderboard files:

```bash
python -m pip install tiktoken huggingface_hub
python summarize_leaderboard.py
```

The script scans local `raw-data/` folders, then reads `submissions/*.json`.
For Hugging Face submissions, it downloads only the small run JSON files into
`.cache/hf-runs/`:

- `evaluation.json`
- `run_metadata.json`
- `results.json`
- `cost_report.json`
- `token_details.json`, when present

It then rewrites:

- `leaderboard/comparison_dcgen.csv`
- `leaderboard/comparison_design2code.csv`
- `leaderboard/dcgen-results.json`
- `leaderboard/design2code-results.json`

Commit the submission manifest and updated files under `leaderboard/`.

## Merge Request Checklist

Before opening a merge request, check:

- Raw artifacts are uploaded to Hugging Face under
  `raw-data/<run_id>/`.
- A matching `submissions/<run_id>.json` manifest is present.
- The manifest includes `run_id`, `dataset`, `method`, `model`,
  `artifact_repo`, and `artifact_path`.
- `evaluation.json`, `run_metadata.json`, `results.json`, and
  `cost_report.json` are present in the Hugging Face artifact folder.
- The run metadata reports the intended dataset, method, model, and instance
  count.
- `python summarize_leaderboard.py` completes without errors.
- The relevant `leaderboard/comparison_*.csv` and
  `leaderboard/*-results.json` files changed as expected.
- No raw HTML/PNG folders, credentials, `.env` files, local caches, or
  unrelated artifacts are included in Git.

Recommended merge request description:

```text
Dataset:
Method:
Model:
Run ID:
Hugging Face artifact path:
Number of instances:
UIBenchKit commit/version:
Notes or known failures:
```

## Leaderboard Data Contract

The UIBenchKit GUI reads leaderboard data from this repository through the
GitHub proxy configured in the GUI. Keep these paths stable:

```text
leaderboard/comparison_dcgen.csv
leaderboard/comparison_design2code.csv
leaderboard/dcgen-results.json
leaderboard/design2code-results.json
```

The CSV files are useful for analysis and table parsing. The JSON files are
formatted for direct GUI consumption.

Important CSV fields include:

- `dataset`
- `method`
- `model`
- `model_date`
- `model_date_source`
- `code_similarity_avg`
- `clip_avg`
- `fg_block_match_avg`
- `fg_text_avg`
- `fg_position_avg`
- `fg_color_avg`
- `fg_clip_avg`
- `code_similarity_all_avg`
- `clip_all_avg`
- `fg_block_match_all_avg`
- `fg_text_all_avg`
- `fg_position_all_avg`
- `fg_color_all_avg`
- `fg_clip_all_avg`
- `text_prompt_tokens_per_instance`
- `vision_prompt_tokens_per_instance`
- `response_tokens_per_instance`
- `run_id`

## Metrics

UIBenchKit currently reports:

- Code similarity: structural similarity between generated and reference HTML.
- CLIP similarity: high-level visual similarity between reference and rendered
  screenshots.
- Fine-grained block match: visual block matching accuracy.
- Fine-grained text similarity: text-level match quality.
- Fine-grained position similarity: block center and layout alignment.
- Fine-grained color similarity: visual color agreement.
- Fine-grained CLIP: CLIP score from the fine-grained evaluation suite.
- Token usage: estimated text prompt, vision prompt, and response tokens per
  instance.

The summarizer includes both successful-sample averages and all-instance
averages where available. All-instance averages help avoid overstating results
when some instances fail.

## GUI Integration

The UIBenchKit GUI fetches leaderboard data from this repository through its
GitHub proxy. For private repositories, configure the GUI deployment with:

```text
GITHUB_TOKEN=<read-only GitHub token>
GITHUB_REPO=<owner>/uibenchkit-experiments
GITHUB_BRANCH=main
```

The token only needs read access to repository contents. The GUI requests:

```text
leaderboard/comparison_<benchmark>.csv
```

and falls back to:

```text
leaderboard/<benchmark>-results.json
```

for benchmarks such as `dcgen` and `design2code`.

## Local Validation

Run the summarizer:

```bash
python summarize_leaderboard.py
```

Then inspect the top of the regenerated CSV:

```bash
head -n 5 leaderboard/comparison_dcgen.csv
head -n 5 leaderboard/comparison_design2code.csv
```

On Windows PowerShell:

```powershell
Get-Content leaderboard\comparison_dcgen.csv -TotalCount 5
Get-Content leaderboard\comparison_design2code.csv -TotalCount 5
```

If you also have the GUI locally, set its GitHub proxy variables to this
repository and verify that the DCGen and Design2Code pages load the new rows.

## Notes

- Raw artifacts live on Hugging Face, not in Git.
- `raw-data/` is only for optional local debugging copies.
- The summarizer skips folders it cannot parse or folders without usable
  evaluation data.
- `token_details.json` is optional but useful for remote submissions because
  the summarizer does not download heavy HTML/PNG artifacts by default.
- Keep generated leaderboard files deterministic by using
  `summarize_leaderboard.py` rather than editing CSV/JSON files by hand.
